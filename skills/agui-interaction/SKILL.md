# AG-UI 交互卡片

在对话里**弹出可交互的卡片**，让用户点按钮做决定，而不是让他打字回答。

- **确认卡**：向用户提问并给出选项（他会点按钮）
- **映射卡**：以表格形式展示结构化数据
- **审批卡**：由平台的权限机制自动弹出（见下文），你不需要手动触发

## 什么时候该用

| 场景 | 用 |
| --- | --- |
| 要做**不可逆/有风险**的动作前（删除、覆盖、发布、扣费） | 确认卡 |
| 有**多个方案**要用户挑一个（不同策略、不同目标环境） | 确认卡 |
| 信息不足、**只有用户知道**，且答案是可枚举的 | 确认卡 |
| 要展示**多行多列**的结构化结果（字段映射、对照表、清单） | 映射卡 |
| 只是打个招呼、报告进度、回答一个普通问题 | ❌ 什么都别弹，直接说 |

**判断标准**：如果用户只需回答"是/否"或"选第几个"，用卡片；如果答案需要打字描述，别用卡片，直接问。

## 确认卡：`demo_confirm_card`

```json
{ "question": "要问用户的那句话（写清楚后果）" }
```

调用后会立即返回一句 `已向用户展示确认卡，等待用户选择。`，**用户的点击会作为下一轮消息回来**。

- `question` 要写清**后果**，不要只写"确定吗"：
  - ✅ `将在生产环境删除 orders 表的历史分区（不可恢复），是否继续？`
  - ❌ `确定吗？`
- 卡片自带「继续 / 取消」两个选项；**不要自己编造用户的回答**。
- 一轮里**只弹一张卡**。用户还没选，就不要继续往下猜。

## 映射卡：`demo_mapping_card`

```json
{ "topic": "要展示的主题" }
```

用来把「字段对应关系 / 对照清单」这类**表格**摆给用户看，比在正文里堆文字清楚得多。

## 审批卡（自动，无需你触发）

当你要调用一个**需要审批的工具**时，平台会自动弹出审批卡，并**暂停**这一轮：

- 用户点「允许」→ 工具继续执行；点「拒绝」→ 该调用被拒。
- 所以：**不要**为了绕过审批去改写成别的工具或让用户手工代做；按正常流程调用即可，审批是给他的一次把关机会。
- 被拒后应当如实告诉用户"该操作未执行"，并给出替代方案。

## 硬性规则

1. **不许假装用户已经确认**。卡片只是"发出去"，没收到他的回复前，任何不可逆动作都不能做。
2. **不许为了显得礼貌而滥弹卡片**。同一件事只问一次；用户已经明确说过的，不要再弹。
3. 卡片是**给人看的**：标题、问题、选项都写具体，别把内部变量名丢给他。
4. 用户选完继续任务时，用一句话说明"按你的选择，接下来……"，别把卡片内容再复述一遍。
