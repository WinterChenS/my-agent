# 本机浏览器扩展实施说明（阶段 A 闭环）

对应设计：`docs/superpowers/specs/2026-10-31-local-browser-extension-design.md`
状态：**已实现并通过本地 + 端到端验证**；商店上架与阶段 C/D 的收尾项见文末「未实现」。

## 1. 一句话

浏览器不再跑在服务器上。Agent 操作的是**用户本机浏览器里已登录的标签页**，
平台只负责「谁能请求什么」，扩展负责「这个设备/标签页/当前状态是否允许执行」。

## 2. 数据流

```
React 网页 ──REST──> Java：配对 / 设备 / 控制会话 / 状态
Agent 工具 ──> BrowserExecutionGateway ──> LocalExtensionExecutor
                                              │  命令帧（requestId/leaseVersion/pageRevision/expiresAt）
                                              ▼
                                   WSS /api/browser/bridge/ws
                                              │
                                              ▼
                        扩展 Service Worker（校验 → chrome.debugger → 结果帧）
                                              │
                                              ▼
                              用户授权的真实标签页（复用登录态）
```

## 3. 已实现（可用的部分）

### 3.1 后端

| 能力 | 位置 |
|---|---|
| 设备配对（deviceCode + userCode + PKCE S256，三处原子消费） | `BrowserPairingService`、`V25__browser_extension.sql` |
| 设备令牌（HMAC 自签，含 credentialVersion；refresh 单次轮换、重用即冻结） | `DeviceTokenService` |
| 长连接通道（**首帧 auth**、5 秒鉴权窗口、单设备单连接、心跳、requestId 关联） | `BrowserBridgeHub`、`BrowserBridgeEndpoint` |
| 控制会话状态机（AWAITING_TAB→HUMAN_CONTROL→AGENT_CONTROL→SUSPENDED/REVOKED，lease 递增） | `BrowserControlSessionService` |
| 执行器抽象 + 本机实现（授权/状态/跨站/过期校验 + 审计） | `BrowserExecutionGateway`、`LocalExtensionExecutor` |
| 工具门面（`browser_*` 走 gateway，remote 模式保留旧路径） | `BrowserToolService`、`BrowserTools` |
| REST（config、pairings、devices、status、control-sessions、WebSocket） | `BrowserExtensionController` |
| 配对/领取/刷新的限流 | 控制器内置滑动窗口（每 IP 10/20/30 次每分钟） |

### 3.2 扩展（`browser-extension/`，MV3，纯 ES module，无需构建）

`manifest.json` 权限：`storage`、`activeTab`、`scripting`、`sidePanel`、`debugger`、`alarms`、`tabs`。

命令执行的动作白名单：`get_snapshot` / `click` / `type_text` / `press_key` / `scroll` /
`navigate` / `capture_screenshot` / `wait_for` / `focus_tab` / `request_tab_grant`。

页面内取值全部走**随扩展打包的固定模板**（`src/debugger.js` 的 `SNIPPETS`），参数以 JSON 数据传入，
不接受后端给的 JS 或 CDP 方法名（符合 MV3 远程代码政策）。

### 3.3 前端

- `BrowserExtensionPanel`：安装引导状态机（未检测到 / 离线 / 已连接未授权 / 已授权 / 你在控制 / 已暂停）、
  设备列表与撤销、配对码手动确认、暂停/交还/撤销。
- `/browser/pair?code=...`：配对确认页（显示设备名、浏览器、剩余时间）。
- `ChatPage` 按后端 `mode` 自动选择面板（`remote` 才用旧的实时画面组件）。

## 4. 关键取舍（和旧实现的差异）

| 项 | 旧（服务端 Chromium） | 新（本机扩展） |
|---|---|---|
| 画面 | CDP screencast 实时 JPEG | **没有镜像**，用户直接看自己的标签页 |
| 登录态 | 服务器 profile，需要重新登录 | 复用用户浏览器已有登录态，不导出 Cookie |
| 资源 | 每用户一个 Chromium（150–300MB） | 服务端零浏览器进程 |
| 人工接管 | 布尔值 + 60 秒自动交还 | 状态机 + leaseVersion，**无自动恢复写操作** |
| 授权粒度 | 整个浏览器 | **单标签页**，换站重新授权 |

「没有实时画面」是刻意的：把真实网页塞进 iframe 会被 X-Frame-Options/CSP 挡住，
也不该把登录态页面嵌进第三方页面。平台面板只显示「连没连 / 授权了哪个页 / 谁在控制」。

## 5. 配置项

```yaml
myagent:
  # 平台对外地址（含端口）。**上线真实环境只改这一个变量**。
  # 扩展打包的平台地址、内测包下载链接、externally_connectable 都由它派生。
  platform:
    public-base-url: ${MYAGENT_PUBLIC_BASE_URL:}

myagent.browser:
  mode: local-extension        # local-extension | remote | disabled
  extension:
    protocol-version: 1
    minimum-version: 0.1.0
    chrome-store-url: ""       # 未上架留空 → 前端显示引导/内测包，不显示失效按钮
    edge-store-url: ""
    allowed-extension-origins: ""   # 留空 = 不校验 Origin，仅靠设备令牌（内测）；生产建议填 chrome-extension://<id>
    pairing-ttl-seconds: 300
    device-token-ttl-seconds: 600
    refresh-token-ttl-seconds: 2592000
    control-session-ttl-seconds: 1800
    max-command-bytes: 65536
    command-timeout-seconds: 25
    token-secret: ""           # **生产必须配置**：留空则每次重启生成临时密钥
    heartbeat-timeout-seconds: 60
    cleanup-millis: 60000
    internal-package-path: ""  # 内测包下载地址，例如 /downloads/my-agent-extension.zip
```

环境变量：`MYAGENT_BROWSER_MODE`、`MYAGENT_BROWSER_EXT_TOKEN_SECRET`、`MYAGENT_BROWSER_EXT_PACKAGE` 等。

## 6. 部署要点

1. **nginx 必须放行 WebSocket**（`deploy/nginx.conf` 已加 `location = /api/browser/bridge/ws`：
   `proxy_http_version 1.1` + `Upgrade`/`Connection` + `proxy_buffering off` + 读超时 90s）。
   不配的话握手会直接 404/400 —— 这是最容易漏的一步。
2. 内测包：`python scripts/build-extension.py` → `deploy/artifacts/my-agent-extension.zip`，
   拷到 `frontend/public/downloads/` 后由前端镜像提供，并设置 `MYAGENT_BROWSER_EXT_PACKAGE`。
3. 生产要设 `MYAGENT_BROWSER_EXT_TOKEN_SECRET`，否则后端重启后扩展需要重连（会触发一次 refresh）。
4. 旧的 `deploy/artifacts/chrome`（275MB）在 `mode=local-extension` 下用不到；阶段 D 可从镜像移除。

## 8. 未实现 / 已知限制

| 项 | 说明 |
|---|---|
| 商店上架（阶段 C） | 需要 Chrome Web Store / Edge Add-ons 的发布者账号、隐私政策、审核；当前只能「加载已解压的扩展程序」 |
| 网页端自动检测扩展是否安装 | 需要固定扩展 ID + `externally_connectable`；现在以「有没有已配对设备」为准，文案已如实说明 |
| content script 自动检测人工输入 | 首期以显式「暂停」为可靠路径（方案允许）；自动检测需要并发人工输入验证 |
| 敏感动作确认（付款/发送前审批卡） | 目前靠系统提示 + 用户手动操作；结构化 `approvalId` 通道未做 |
| iframe / OOPIF | 跨域 iframe 不纳入（快照只取主 frame）；截图在存在跨域 iframe 时未做专项拦截 |
| 多设备并发 | 同一会话绑定一台设备；一个设备同时一个活跃控制会话 |
| 旧 remote 模式 | 代码保留（`mode=remote`），未删除；实时画面链路仍可用 |
| 页面版本语义 | `pageRevision` 由扩展在每次成功动作后递增，不是浏览器原生的 document 版本号 |

## 9. 体验优化批次（连接便利 / 侧边栏画面 / 面板交互）

### 9.1 连接便利（问题：装完还要填地址、手动配对）

| 改动 | 实现 |
|---|---|
| 固定扩展 ID | `browser-extension/manifest.json` 的 `key`（RSA 公钥）；ID = `ijklemfakolbnlbgephimnjlaejjkmpp`。私钥 `.extension-key.pem` 已 gitignore |
| 平台地址烘焙 | `scripts/build-extension.py --platform-url http://192.168.3.10:18080` 写入 `src/config.js`；用户装完不用填 |
| 网页检测扩展 | `manifest.externally_connectable.matches` 精确到部署域名；网页 `chrome.runtime.sendMessage(extensionId, {type:'bridge.ping'})` |
| 一键连接 | 网页 `bridge.pair` → 扩展创建配对并返回 userCode → 网页（已登录）调 approve → 扩展后台领凭证。用户只点一次 |
| 浏览器识别 | UA 判 Chrome/Edge，面板里显示"检测到你正在使用 X" |
| 执行通道不变 | 外部消息**只**能 ping/pair/state/autoGrant，不能执行任何浏览器动作 |

> 安装本身仍受 Chrome 限制（不能网页静默安装），内测期只能「加载已解压的扩展程序」；
> 上架商店后才是真一键。

### 9.2 侧边栏实时画面（方案 A）

- `background`：`Page.startScreencast`（jpeg/55/900px），帧经 `chrome.runtime.sendMessage` 送到侧边栏；
  **ack 立即发送**（服务端实现时踩过同样的坑：不 ack 只推一帧）。
- `sidepanel`：canvas 等比 `contain` 显示；点击/滚轮/按键按 `getBoundingClientRect` 换算回页面坐标再注入；
  10fps 节流。
- 为什么不是 iframe：绝大多数站点 `X-Frame-Options`/CSP `frame-ancestors` 拒绝被嵌，通用方案不成立。

### 9.3 自动接管（一次性全局授权）

- 侧边栏开关 + 网页面板卡片：`myagent.autoGrant` 存在扩展本地。
- 开启后收到命令且没有授权标签页时，自动接管**当前活动标签页**（`chrome.debugger` 不需要 activeTab），
  并把服务端下发的 `leaseVersion` 同步到本地（否则会被判成"命令过期"）。
- 关闭时保持"每个标签页手动授权"。两种情况都保留暂停/撤销。

### 9.4 面板交互（问题 3）

- 「产物 / 浏览器」按钮改为 `position: fixed`：未展开贴窗口右边，展开后贴着面板左边缘，
  用 `transition-[right]` 跟随（铺满时被夹在可视区内，仍可点）。
- 面板**常驻渲染**，`open` 控制宽度（0 ↔ N）并做 200ms 过渡 —— 打开/收起视觉上就是"聊天区自动让位"。
- 宽度上限 = 聊天区域容器宽度（`[data-chat-root]`），**允许铺满**；下限 320px（否则拖成一条缝找不回来）。

### 9.5 待你在真实浏览器里验收的点

以下三项我只做了静态校验（语法/逻辑/类型），**没有在真实 Chrome 里端到端跑过**（本地 headless 环境装不了扩展）：

1. 网页是否显示「已检测到浏览器扩展 vX」+「一键连接」（`externally_connectable` 生效）；
2. 一键连接后是否自动变「已配对」；
3. 侧边栏「显示画面」后是否能看到页面镜像、点击/滚动是否生效。

### 9.6 Agent 自己打开网页（不再要用户手动开）

`browser_open(url)` 走的是 `request_tab_grant`，之前只在扩展里"请求授权"，没打开页面 —— 用户得自己敲地址。现在：

- 扩展收到 `request_tab_grant` 时就 `chrome.tabs.create({url})` 打开（已授权且同站则就地导航），
  等 tab `status=complete` 后再继续，所以 Agent 一次调用就能拿到"页面已就绪"。
- **自动接管开启时**：打开 → attach → 上报 `AGENT_CONTROL`，服务端直接进 Agent 控制
  （用户已全局授权），并把递增后的 `leaseVersion` 通过 `session.update` 推回扩展，
  避免下一步命令被判"过期"。
- **未开启自动接管时**：页面已打开，只需在侧边栏点一次「授权当前标签页」。
- 服务端 `LocalExtensionExecutor` 在 `AWAITING_TAB` 后会等最多 5 秒看扩展是否已上报授权：
  自动接管是毫秒级的，通常一次工具调用就完成；手动模式超时后提示用户点一次授权。

### 9.7 「每次都要授权」的三个原因（都修了）

用户反馈：授权一次之后 Agent 每次操作都还要再授权。拆开看是三个独立问题：

1. **授权后默认停在 HUMAN_CONTROL**（方案 10.1 原设计），所以授权完还要再点一次「交还」。
   → 改成**授权即 AGENT_CONTROL**：只有扩展明确上报 `HUMAN_CONTROL`（用户点了「我要自己操作」）才停在人类控制。
2. **每次 `browser_open` 都新开标签页** → 新标签页等于"没授权过"，看起来就是要重授权。
   → 改成**优先复用已授权的标签页**（同站必复用；跨站仅在「自动接管」开启时复用）。
3. **换对话就换 control session** → 每个新 conversation 第一次都要授权。
   → `ensureSession` 先看**同一台设备最近一个未结束的会话**，有就复用并改绑 conversation。

另外：**第一次授权顺手把「自动接管」打开**（只有用户显式关过才保持关闭），
这样"授权一次 = 之后自动"，不用再去侧边栏找开关。

### 9.8 Agent 专用浏览器窗口（popup，方案 A）

用户问「能不能用 Chrome 的弹出子页面 / iframe 嵌入」，结论：

- **iframe 不可行**：站点普遍设 `X-Frame-Options`/CSP `frame-ancestors` 拒绝被嵌；
  即便能嵌，`chrome-extension://` 页面里的 iframe 是第三方上下文，SameSite Cookie 不发送 → 登录态失效。
- **popup 窗口可行且已实现**：`chrome.windows.create({url, type:'popup'})` 是**顶级浏览上下文**，
  真实渲染、登录态完整、可被 CDP 操作；位置用「聚焦窗口右侧、宽度 560」推算（不需要 system.display 权限）。

实现：`openUrlForCommand` 改为在专用窗口打开；窗口 id 记在 `myagent.agentWindow`，
之后所有导航都复用同一个窗口（不再新开标签页、不占用户页面）；
窗口被用户关掉时 `chrome.windows.onRemoved` → 会话置 `SUSPENDED` + 清 grant，
避免"Agent 以为还能操作"。

限制（写清楚）：popup 是独立窗口，**不能嵌进平台页面**；上面也无法叠加我们自己的按钮
（那是站点 DOM），控制 UI 仍在扩展侧边栏。

### 9.9 平台地址不再写死在代码里

之前内测包链接/扩展里的平台地址是硬编码 `http://192.168.3.10:18080` —— 上线真实环境会出错。现在统一从配置派生：

| 位置 | 现在怎么来 |
|---|---|
| `GET /api/browser/extension/config` 的 `platformUrl` / `extensionPackageUrl` | `myagent.platform.public-base-url`（`MYAGENT_PUBLIC_BASE_URL`）拼 `internal-package-path` |
| 前端「下载内测包」按钮 | 直接用后端给的**绝对地址**；后端没配时退回相对路径（用当前来源），前端不拼任何 IP |
| 扩展里的默认平台地址（`src/config.js`） | 打包时 `scripts/build-extension.py` 从 `MYAGENT_PUBLIC_BASE_URL` 写入；**故意不设默认值**，缺失就报错 |
| `manifest.externally_connectable.matches` | 同一次打包由该地址生成（+ 本地开发地址） |

上线流程：改 `.env` 的 `MYAGENT_PUBLIC_BASE_URL=https://你的域名` → `./scripts/build-artifacts.sh`（会自动重打扩展包并拷进前端静态目录）→ `deploy-docker.py`。
用户已装的扩展需要重新下载一次（`externally_connectable` 里是精确域名）。

### 9.10 自动接管默认开启（popup 窗口里没有授权入口）

popup 窗口没有工具栏/扩展图标，用户在里面**无法完成「授权这个标签页」** —— 不默认自动接管就直接死锁。

- `myagent.autoGrant.v2` 默认 `true`（升键名，老用户也会立刻拿到新默认值，不用去找开关）
- 自动接管**只操作 Agent 专用窗口里的标签页**（`autoGrantTab` 优先取 `myagent.agentWindow`），
  绝不把用户当前正在看的页面（网银/邮箱）当操作目标；没有专用窗口时才退到当前活动标签页
- 侧边栏 / 网页面板保留开关，可随时关掉改回逐页手动授权；「暂停」始终有效
