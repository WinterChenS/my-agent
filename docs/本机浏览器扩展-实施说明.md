# 本机浏览器扩展实施说明（阶段 A 闭环）

对应设计：`docs/superpowers/specs/2026-10-31-local-browser-extension-design.md`
状态：**已实现并通过本地 + 端到端验证**；商店上架与阶段 C/D 的收尾项见文末「未实现」。

## 1. 一句话

浏览器不再跑在服务器上。Agent 操作的是**用户本机浏览器里已登录的标签页**，
平台只负责「谁能请求什么」，扩展负责「这个设备/标签页/当前状态是否允许执行」。

## 2. 数据流

```
React 网页 ──REST──> Java：配对 / 设备 / 控制会话 / 状态
Agent 工具 ──> BrowserExecutionGateway ──> LocalExtensionExecutor
                                              │  命令帧（requestId/leaseVersion/pageRevision/expiresAt）
                                              ▼
                                   WSS /api/browser/bridge/ws
                                              │
                                              ▼
                        扩展 Service Worker（校验 → chrome.debugger → 结果帧）
                                              │
                                              ▼
                              用户授权的真实标签页（复用登录态）
```

## 3. 已实现（可用的部分）

### 3.1 后端

| 能力 | 位置 |
|---|---|
| 设备配对（deviceCode + userCode + PKCE S256，三处原子消费） | `BrowserPairingService`、`V25__browser_extension.sql` |
| 设备令牌（HMAC 自签，含 credentialVersion；refresh 单次轮换、重用即冻结） | `DeviceTokenService` |
| 长连接通道（**首帧 auth**、5 秒鉴权窗口、单设备单连接、心跳、requestId 关联） | `BrowserBridgeHub`、`BrowserBridgeEndpoint` |
| 控制会话状态机（AWAITING_TAB→HUMAN_CONTROL→AGENT_CONTROL→SUSPENDED/REVOKED，lease 递增） | `BrowserControlSessionService` |
| 执行器抽象 + 本机实现（授权/状态/跨站/过期校验 + 审计） | `BrowserExecutionGateway`、`LocalExtensionExecutor` |
| 工具门面（`browser_*` 走 gateway，remote 模式保留旧路径） | `BrowserToolService`、`BrowserTools` |
| REST（config、pairings、devices、status、control-sessions、WebSocket） | `BrowserExtensionController` |
| 配对/领取/刷新的限流 | 控制器内置滑动窗口（每 IP 10/20/30 次每分钟） |

### 3.2 扩展（`browser-extension/`，MV3，纯 ES module，无需构建）

`manifest.json` 权限：`storage`、`activeTab`、`scripting`、`sidePanel`、`debugger`、`alarms`、`tabs`。

命令执行的动作白名单：`get_snapshot` / `click` / `type_text` / `press_key` / `scroll` /
`navigate` / `capture_screenshot` / `wait_for` / `focus_tab` / `request_tab_grant`。

页面内取值全部走**随扩展打包的固定模板**（`src/debugger.js` 的 `SNIPPETS`），参数以 JSON 数据传入，
不接受后端给的 JS 或 CDP 方法名（符合 MV3 远程代码政策）。

### 3.3 前端

- `BrowserExtensionPanel`：安装引导状态机（未检测到 / 离线 / 已连接未授权 / 已授权 / 你在控制 / 已暂停）、
  设备列表与撤销、配对码手动确认、暂停/交还/撤销。
- `/browser/pair?code=...`：配对确认页（显示设备名、浏览器、剩余时间）。
- `ChatPage` 按后端 `mode` 自动选择面板（`remote` 才用旧的实时画面组件）。

## 4. 关键取舍（和旧实现的差异）

| 项 | 旧（服务端 Chromium） | 新（本机扩展） |
|---|---|---|
| 画面 | CDP screencast 实时 JPEG | **没有镜像**，用户直接看自己的标签页 |
| 登录态 | 服务器 profile，需要重新登录 | 复用用户浏览器已有登录态，不导出 Cookie |
| 资源 | 每用户一个 Chromium（150–300MB） | 服务端零浏览器进程 |
| 人工接管 | 布尔值 + 60 秒自动交还 | 状态机 + leaseVersion，**无自动恢复写操作** |
| 授权粒度 | 整个浏览器 | **单标签页**，换站重新授权 |

「没有实时画面」是刻意的：把真实网页塞进 iframe 会被 X-Frame-Options/CSP 挡住，
也不该把登录态页面嵌进第三方页面。平台面板只显示「连没连 / 授权了哪个页 / 谁在控制」。

## 5. 配置项

```yaml
myagent.browser:
  mode: local-extension        # local-extension | remote | disabled
  extension:
    protocol-version: 1
    minimum-version: 0.1.0
    chrome-store-url: ""       # 未上架留空 → 前端显示引导/内测包，不显示失效按钮
    edge-store-url: ""
    allowed-extension-origins: ""   # 留空 = 不校验 Origin，仅靠设备令牌（内测）；生产建议填 chrome-extension://<id>
    pairing-ttl-seconds: 300
    device-token-ttl-seconds: 600
    refresh-token-ttl-seconds: 2592000
    control-session-ttl-seconds: 1800
    max-command-bytes: 65536
    command-timeout-seconds: 25
    token-secret: ""           # **生产必须配置**：留空则每次重启生成临时密钥
    heartbeat-timeout-seconds: 60
    cleanup-millis: 60000
    internal-package-path: ""  # 内测包下载地址，例如 /downloads/my-agent-extension.zip
```

环境变量：`MYAGENT_BROWSER_MODE`、`MYAGENT_BROWSER_EXT_TOKEN_SECRET`、`MYAGENT_BROWSER_EXT_PACKAGE` 等。

## 6. 部署要点

1. **nginx 必须放行 WebSocket**（`deploy/nginx.conf` 已加 `location = /api/browser/bridge/ws`：
   `proxy_http_version 1.1` + `Upgrade`/`Connection` + `proxy_buffering off` + 读超时 90s）。
   不配的话握手会直接 404/400 —— 这是最容易漏的一步。
2. 内测包：`python scripts/build-extension.py` → `deploy/artifacts/my-agent-extension.zip`，
   拷到 `frontend/public/downloads/` 后由前端镜像提供，并设置 `MYAGENT_BROWSER_EXT_PACKAGE`。
3. 生产要设 `MYAGENT_BROWSER_EXT_TOKEN_SECRET`，否则后端重启后扩展需要重连（会触发一次 refresh）。
4. 旧的 `deploy/artifacts/chrome`（275MB）在 `mode=local-extension` 下用不到；阶段 D 可从镜像移除。

## 8. 未实现 / 已知限制

| 项 | 说明 |
|---|---|
| 商店上架（阶段 C） | 需要 Chrome Web Store / Edge Add-ons 的发布者账号、隐私政策、审核；当前只能「加载已解压的扩展程序」 |
| 网页端自动检测扩展是否安装 | 需要固定扩展 ID + `externally_connectable`；现在以「有没有已配对设备」为准，文案已如实说明 |
| content script 自动检测人工输入 | 首期以显式「暂停」为可靠路径（方案允许）；自动检测需要并发人工输入验证 |
| 敏感动作确认（付款/发送前审批卡） | 目前靠系统提示 + 用户手动操作；结构化 `approvalId` 通道未做 |
| iframe / OOPIF | 跨域 iframe 不纳入（快照只取主 frame）；截图在存在跨域 iframe 时未做专项拦截 |
| 多设备并发 | 同一会话绑定一台设备；一个设备同时一个活跃控制会话 |
| 旧 remote 模式 | 代码保留（`mode=remote`），未删除；实时画面链路仍可用 |
| 页面版本语义 | `pageRevision` 由扩展在每次成功动作后递增，不是浏览器原生的 document 版本号 |
