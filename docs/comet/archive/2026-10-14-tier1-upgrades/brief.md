# 目标

补齐 Agent 平台「第一梯队」能力（用户 2026-10-12 指定），解决已经踩到的四类问题：

1. **多模态输入**：用户常传截图，但目前图片只是被**当成文件**落在工作区（模型拿到的是路径，不是图像）。
   需要把图片作为**图像内容**直接喂给模型；并在**模型配置里加一个「是否多模态」开关**——只有开启的模型才允许/才会收到图片。
2. **上下文可见 + 可控**：会话上下文会无上限增长（实测出现过单会话 1.8MB → 请求 127 万 tokens 被厂商拒绝，且**无法就地自救**）。
   需要：显示本会话上下文用量、支持「压缩/清空该会话上下文」、接近阈值时给出提示。
3. **运行任务可持久 + 可通知**：当前 run 是**内存态**，后端重启即在跑的任务全丢；
   长任务结束也没有任何通知（用户只能盯着屏幕）。
4. **支出控制**：审计已能按模型价格算成本，但没有**配额与告警**。需要每用户/每 Agent 的额度与超限行为。

# 范围

## ① 多模态输入 + 模型多模态开关

- `llm_model` 增加 `multimodal` 开关（默认关闭），模型页可编辑并显示。
- 前端：发送消息时，若**该会话的 Agent 所用模型已开启多模态**，把本次附件中的图片作为
  `ImagePart`（`{type:"image", source:{type:"data", value:<base64>, mimeType}}`）**随消息一起发送**；
  非图片附件仍走既有「上传 + 物化 + 附件清单」路径。
- 后端：模型未开启多模态时**剥离图片内容块**并在回复里说明（不静默丢），避免厂商 400；
  开启时按官方适配器把 `ImagePart` 转成 `ImageBlock` 交给模型（已确认官方 AG-UI 适配器支持）。
- 体积与安全：单图上限（如 5MB）、仅允许常见栅格格式（png/jpeg/webp/gif）、每轮图片数量上限（如 5）。

## ② 上下文可见 + 可控

- 会话级上下文用量：新增查询接口返回「当前上下文 tokens 估算 / 压缩阈值 / 是否已压缩过」，
  前端在**发送键旁用圆环**显示占比（三档颜色，点开浮层看细节与动作）。
  注：最初写的是「输入框上方用量条」，用户看过之后明确要求改成圆环 + 点开详情（已按后者实现并验收）。
- 「压缩上下文」「清空上下文」两个动作：走官方压缩能力与状态存储清理（清空 = 清掉该会话的
  `agent_state`，聊天记录保留、模型从零开始），操作后给明确反馈。
- 超过阈值时自动压缩（已有）＋**压缩后在前端提示一次**（用户知道发生了什么）。

## ③ 运行任务可持久 + 可通知

- run 状态持久化到库（`agent_run` 表：threadId/runId/状态/开始时间/结束时间/已生成文本摘要），
  后端重启后前端仍能看到「该会话上一次运行的状态」。
- 长任务完成通知：前端在**非当前会话**的 run 结束时给一条站内提示（toast/角标）；可选浏览器通知（需用户授权）。
- 明确不做：分布式任务队列（超出本轮范围，登记 backlog）。

## ④ 支出控制（配额 + 告警）

- `sys_user` / `agent` 增加额度配置（日/月，单位与货币跟模型价格一致）。
- 运行前检查：超限则**拒绝发起**并给出明确提示（可选「仅告警不拦截」）。
- 审计看板/顶栏显示「本日/本月已用成本 / 额度」，超 80% 提示、超 100% 按配置拦截。

# 非目标

- 不做 RAG/向量检索、不做语音/视频输入（只做图片）、不做分布式任务队列、不做跨货币汇率换算。
- 不改动现有 AG-UI 事件契约（只新增内容块用法与查询接口）。

# 验收示例

1. 模型多模态开关
   - 输入：编辑模型，打开「多模态」开关并保存
   - 期望：模型列表/详情显示为已开启；关闭时不可发送图片

2. 图片真正喂给模型
   - 输入：向已开启多模态的模型发起一轮，附带一张图片
   - 期望：发给模型的请求里包含图像内容（**桩捕获的请求体为证**：出现 image 内容块/base64），且模型据此回答

3. 未开启多模态时的行为
   - 输入：向未开启多模态的模型附带图片发送
   - 期望：图片被剥离（不发给模型），前端/回复里明确提示「该模型未开启多模态，图片未发送」，不出现厂商 400

4. 图片限制
   - 输入：发送超过大小上限的图片 / 非法格式 / 超过数量上限
   - 期望：明确业务错误提示，不影响文本消息发送

5. 上下文用量可见
   - 输入：打开一个较长会话
   - 期望：**发送键旁的圆环**显示上下文用量与阈值（百分比 + 三档颜色），接近阈值时有醒目提示；点开浮层看细节

6. 上下文可控
   - 输入：点「压缩上下文」
   - 期望：触发官方压缩并给出反馈（压缩前后用量下降）
   - 输入：点「清空上下文」
   - 期望：该会话模型上下文被清空（`agent_state` 无该会话状态），聊天记录仍在，随后对话正常

7. 运行状态持久化
   - 输入：发起一轮后重启后端，再打开该会话
   - 期望：能看到该会话上一轮的状态，不是「什么都没有」。
    **提示只在界面上看不到时才出现**（用户反馈收紧）：已完成的答案已在聊天记录里 → 不提示；
    已中断（如服务重启）或出错 → 一律提示并带原因。

8. 长任务完成通知
   - 输入：切到别的会话，让原会话的 run 在后台跑完
   - 期望：收到站内提示（toast/角标），点击可跳回该会话

9. 支出配额
   - 输入：为某用户设置很小的日额度，连续对话直到超限
   - 期望：超限后按配置**拒绝发起**（或仅告警），提示当前用量与额度；审计看板显示已用/额度

# 约束与不变量

- G1 不新增非必要依赖；G2 分层不变；G3 既有接口与事件契约不变（只新增）；G5 DDL 只经 Flyway；G8 只用官方能力（图片走官方 `ImageBlock`/适配器，压缩走官方 `CompactionConfig`）。
- 不变量：审计 token 统计口径不变；配额只在其上增加。

# 决定

- D1 多模态是**模型级开关**（用户明确要求）；未开启时图片不发送（而不是让厂商报错）。
- D2 图片以 **base64 内联**随消息发送（不依赖厂商能否访问我们内网 MinIO 的直链）。
- D3 「清空上下文」= 删除该会话的框架状态（`agent_state`），**保留**聊天记录（用户可继续对话）。
- D4 运行状态持久化用一张新表；**不引入**外部队列（本轮非目标）。
- D5 配额为「日 + 月」两级，单位与货币跟模型价格；超限行为可配（拦截/仅告警）。

# 验证期望

- ① 必须有**端到端证据**：桩捕获的请求体里出现图像内容（不能只证明开关存取）。
- ②④ 必须有查询/拦截的实际接口输出与 SQL/界面证据。
- ③ 必须有「重启后端后状态仍可见」的实测。
- 由独立验收员复核全部验收项。
