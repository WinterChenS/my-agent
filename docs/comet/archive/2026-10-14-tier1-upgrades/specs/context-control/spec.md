# context-control

## Purpose

让会话上下文**可见且可控**：显示用量、一键压缩、一键清空，避免"上下文爆了只能新建会话"。

## 设计

- 查询接口：返回该会话「当前上下文 tokens 估算 / 压缩触发阈值 / 保留阈值 / 是否已压缩过」。
- 「压缩上下文」：触发官方压缩（`CompactionConfig` 能力）并回报压缩前后用量。
- 「清空上下文」：删除该会话的框架状态（`agent_state` 该 threadId 的行）——**保留聊天记录**，模型从零开始。
- 前端：**发送键旁的圆环**显示当前上下文占比（用户明确要求，取代最初的「输入框上方用量条」）：
  环的填充比例 = 已用 / 压缩触发阈值，颜色三档（绿 / 黄 ≥80% / 红 ≥100%）、圆心显示百分比；
  点开浮层看细节（已用与阈值、消息条数、保留阈值、是否压缩过、摘要预览、状态提示），
  浮层内提供「压缩上下文」与「清空上下文」两个动作 + 结果反馈；清空需**二次确认**。
- 自动压缩发生后，前端提示一次（用户知道发生了什么）。

## 边界

- 不改 token 统计口径（审计不变）。
- 清空上下文不等于删除会话（消息与产物都保留）。

## 验收标准

- 长会话能看到用量与阈值（**发送键旁的圆环**：百分比 + 三档颜色；点开浮层看细节）；接近阈值有醒目提示。
- 「压缩上下文」有反馈且用量下降。
- 「清空上下文」需二次确认；确认后 `agent_state` 无该会话行、聊天记录仍在、随后对话正常。
