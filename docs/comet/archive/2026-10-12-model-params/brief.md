# 目标

大模型维护需要完整、且**每一项都真正生效**的配置项（用户 2026-10-12 提出）：

1. 温度（temperature）
2. Top-N（Top-P 核采样）
3. 上下文长度（context window）
4. 输出长度（max output tokens）
5. 每百万 token 的价格（人民币 / 美元）

"生效"的定义：温度、Top-N、输出长度必须随每次请求下发给模型；上下文长度必须参与校验并驱动上下文治理；
价格必须让审计看板能算出成本（按模型、按货币）。

# 范围

1. **数据模型**：`llm_model` 把上述参数从 `params_json` 提升为显式列
   （`temperature` / `top_p` / `context_window` / `max_tokens` / `price_input` / `price_output` / `price_currency`），
   从历史 `params_json` 回填，并加取值范围约束（温度 0–2、Top-P (0,1]、长度为正、价格非负、货币 CNY|USD）。
2. **接口与校验**：模型新建/更新接受这七项；校验范围，并强制 **输出长度 ≤ 上下文长度**
   （避免"补全预算占满窗口"这种会被厂商以 `context_length_exceeded` 拒绝的配置）。
3. **生效接线**：
   - 温度 / Top-N / 输出长度 → 官方 `GenerateOptions`（→ 实际请求体）。优先级：**Agent 级覆盖 > 模型级兜底**
     （并修掉"Agent 级为空时覆盖掉模型级"的旧问题）。
   - 上下文长度 → ① 参与上述校验 ② 驱动官方压缩阈值 `min(配置值, 窗口×60%)`。
   - 价格 → 审计按模型价格计算成本（`byModel` 增单价与成本，`summary` 按货币汇总；不同货币不混加）。
4. **前端**：模型页表单可编辑这七项（含前端校验与说明）；模型列表显示「采样 / 长度」与「价格（每百万 token）」；
   审计看板按模型显示「单价（入/出）」与「成本」。

# 非目标

- 不做"按模型分档计费/折扣/阶梯价"等复杂计价；只做"输入价 + 输出价（每百万 token）+ 货币"。
- 不做跨货币汇率换算（不同货币分别汇总，混合时标记 MIXED）。
- 不改动 Agent 顶层的 `temperature`/`max_tokens` 覆盖能力（保留为覆盖项）。

# 验收示例

1. 模型配置项可写可读
   - 输入：新建模型时给出温度 0.35、Top-P 0.85、上下文 128000、输出 2048、输入价 1.5、输出价 6、货币 CNY
   - 期望：创建成功，且查询该模型时这七项原值返回

2. 取值范围校验
   - 输入：温度 3 / Top-P 0 / 上下文 0 / 价格为负 / 货币 EUR
   - 期望：各自返回明确的业务错误（400），不写入

3. 输出长度不得超过上下文长度
   - 输入：上下文 1000 + 输出 5000
   - 期望：返回 400，提示「输出长度（5000）不能大于上下文长度（1000）」

4. 温度 / Top-N / 输出长度随请求下发（真正生效）
   - 输入：用上述模型发起一轮对话
   - 期望：实际发给模型的请求体里带上 `temperature=0.35`、`top_p=0.85`、`max_tokens=2048`

5. 上下文长度驱动上下文治理
   - 输入：模型配置上下文长度（如 8000）
   - 期望：历史压缩触发阈值取 `min(配置值, 窗口×60%)`（即 4800），窗口小的模型不会被压爆

6. 价格驱动审计成本（真正生效）
   - 输入：一次用量为 11 输入 tokens + 5 输出 tokens，模型价格 1.5 / 6（每百万 CNY）
   - 期望：审计 summary 的 `costTotal = 4.65e-05`、`costCurrency = CNY`；`byModel` 中该模型带单价与成本

7. 前端可维护
   - 输入：管理台 → 模型页 → 编辑模型
   - 期望：温度 / Top-N / 上下文长度 / 输出长度 / 输入价格 / 输出价格 / 价格货币 七个输入项可见可改并保存成功；
     列表显示「采样 / 长度」与「价格（每百万 token）」两列

8. 审计看板显示成本
   - 输入：打开审计看板
   - 期望：按模型分布里显示「单价（入/出）」与「成本」（带货币）

# 约束与不变量

- G1：不新增第三方依赖。
- G2：AgentScope API 仅出现在 `agui/` 等既有允许的包；模型配置包不引入 AgentScope。
- G3：模型接口字段**新增**（向后兼容：`params` 仍接受，但不再作为这些参数的主存储）。
- G5：DDL 只经 Flyway（`V7__llm_model_params.sql`）；`mvn verify` 与前端 lint/build/test 全绿。
- 不变量：审计的 token 统计口径不变，只在其上增加成本维度。

# 决定

- D1 参数存储：从 `params_json` 提升为**显式列**（可校验、可查询、可聚合），历史值一次性回填。
- D2 优先级：温度与输出长度按「Agent 级 > 模型级」；Top-N 只有模型级；上下文长度只属模型级。
- D3 长度关系必须自洽：**输出长度 ≤ 上下文长度**（避免厂商侧 `context_length_exceeded`）。
- D4 上下文长度参与治理：压缩触发阈值 = `min(配置值, 窗口×60%)`。
- D5 计价口径：输入价/输出价均为「每百万 token」，货币取模型配置（CNY/USD）；不同货币不混加（混合标 MIXED）。

# 验证期望

- 每项验收都要有可复核证据：接口返回、**桩捕获的实际请求体**、SQL 结果、浏览器截图。
- "生效"必须有端到端证据（不能只证明字段存取）。
