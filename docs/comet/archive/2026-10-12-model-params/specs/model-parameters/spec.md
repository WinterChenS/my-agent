# model-parameters

## Purpose

让大模型的运维参数完整、可校验、**且每一项都真正作用于运行时**：温度、Top-N、上下文长度、输出长度、价格（每百万 token，CNY/USD）。

## 数据模型

`llm_model` 显式列（`V7__llm_model_params.sql`，并从 `params_json` 回填）：

| 列 | 含义 | 约束 |
|---|---|---|
| `temperature` | 采样温度 | 0–2 |
| `top_p` | Top-P 核采样（Top-N） | (0, 1] |
| `context_window` | 上下文窗口长度（token） | > 0 |
| `max_tokens` | 单次输出长度上限（token） | > 0 且 ≤ `context_window` |
| `price_input` | 输入价（每百万 token） | ≥ 0 |
| `price_output` | 输出价（每百万 token） | ≥ 0 |
| `price_currency` | 价格货币 | CNY / USD |

`params_json` 保留（历史兼容与扩展参数），但这五项以显式列为准。

## 生效路径（关键）

```
模型配置(显式列) ─┬─ 温度 / Top-P / 输出长度 ─→ AgentFactory 合并参数 ─→ ModelFactory ─→ GenerateOptions ─→ 厂商请求体
                  ├─ 上下文长度 ─→ ① 校验（输出≤上下文） ② 压缩阈值 = min(配置值, 窗口×60%)
                  └─ 价格 ─→ 审计聚合（byModel 单价+成本；summary 按货币汇总）
```

- **优先级**：温度与输出长度按「Agent 级覆盖 > 模型级」；Top-N、上下文长度只属模型级。
- **审计口径**：`成本 = 输入tokens/1e6 × 输入价 + 输出tokens/1e6 × 输出价`，货币取模型配置；
  不同货币不混加（`s.costCurrency = MIXED`）。

## 前端

- 模型页表单：七个输入项（温度 / Top-N / 上下文长度 / 输出长度 / 输入价格 / 输出价格 / 价格货币），
  保存前做「输出≤上下文」的前端校验。
- 模型列表：「采样 / 长度」（温度·TopN·上下文·输出）与「价格（每百万 token）」两列。
- 审计看板：按模型分布增加「单价（入/出）」与「成本」列。

## 边界

- 不做阶梯价/折扣/汇率换算。
- 上下文长度不改变 token 统计口径，只影响校验与压缩阈值。

## 验收标准

- 七项参数创建/更新后能原值读回；非法值（温度>2、Top-P≤0、长度≤0、价格为负、货币非 CNY/USD）返回 400。
- 输出长度 > 上下文长度 → 400 明确提示。
- 发起对话时，实际请求体带上配置的温度、Top-P、输出长度（**桩捕获的请求体为证**）。
- 上下文长度驱动压缩阈值（`min(配置值, 窗口×60%)`，有单测）。
- 审计按模型价格算出成本，数值与手算一致（含货币）。
- 前端模型页可编辑七项并保存成功；列表与审计看板显示对应列（截图）。
