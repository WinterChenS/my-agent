# chat-skill-picker

## Purpose

在对话输入框通过输入 `/` 选择 Skill；选中后 Skill 在输入框中表现为**不可编辑的块**，可删除。

## 交互

- 输入 `/`（位于行首或空格之后）时弹出 Skill 选择面板：列出 **ENABLED** 的 Skill（名称 + 描述），支持键盘上下选择与回车确认、Esc 关闭。
- 选中后：
  - 输入框中插入一个**不可编辑的 chip/块**（显示 `/<skill-name>`），键盘无法在其内部编辑，退格可整体删除；
  - `/` 触发的查询文本被清除，不残留在正文中。
- 同一消息可包含多个 Skill 块；重复选择同名 Skill 不重复插入。
- 发送后消息正文 = 纯文本 + 附带的 `skillIds` 列表。

## 服务端语义（D21）

- 请求携带 `skillIds`（会话级生效，**并入**该 Agent 已绑定的技能集合）。
- `AgentFactory` 构建时把「Agent 绑定技能 ∪ 会话选中的技能」交给 AgentScope 官方 `SkillFilter`（`SkillFilter.only(...)`）。
- 内容仍按官方**渐进式披露**加载（系统提示词注入名称/描述，正文按需读取），不把整篇 Skill 正文硬塞进提示词。
- 若会话选中的 Skill 已被删除/禁用：忽略并在响应的事件流中给出提示，不阻断本轮对话。

## 数据

- 会话级选择保存在 `chat_session` 或请求级传入（实现可选）；至少保证**同一会话内**后续轮次沿用已选技能，直到用户删除该块。

## 验收标准

- 输入 `/` 出现 Skill 列表（仅 ENABLED）；选择后输入框中出现不可编辑块，正文不含 `/` 查询串。
- 块可整体删除；删除后该技能不再对该会话生效。
- 发送后，被选中的 Skill 出现在 Agent 可见技能集合中（可用「Skill 要求回复末尾加标记」的桩场景验证）。
- 选择已禁用的 Skill 不会导致本轮报错。
- 前端单测覆盖：`/` 触发、选择插入、删除、以及序列化出的 `skillIds`。
