# Agent 平台技术方案

> 项目代号：`my-agent`（前后端分离的 Agent 平台）
> 本文档是唯一事实来源（Single Source of Truth）。实现 agent 在写代码前必须通读本文档与《任务列表.md》，任何偏离都需要先在 PR/任务记录中说明理由。

**职责边界（防止跑偏的第一道门）：**

- Spring Boot 层只做：CRUD 配置、鉴权、会话管理、审计落库、把 DB 配置"翻译"成 AgentScope 对象、托管 `/agui/run` 端点。**不自己实现任何推理循环、工具调用、MCP 协议**——这些全部由 AgentScope 承担。
- 前端只做：渲染 AG-UI 事件流 + 管理台表单。**不解析模型响应、不拼 prompt、不直接调用模型 API**。

## 4. 后端模块与包结构

```
backend/agent-server/src/main/java/com/myagent/
├── AgentServerApplication.java
├── config/          # SecurityConfig, RedisConfig, MybatisPlusConfig, JacksonConfig, AgentScopeConfig
├── common/          # Result<T>, PageResult, BizException, GlobalExceptionHandler, CryptoService
├── auth/            # AuthController, JwtService, UserDetailsServiceImpl, JwtAuthFilter
├── modelconfig/     # controller / service / mapper / entity   —— 大模型配置
├── agentconfig/     # controller / service / mapper / entity   —— Agent 配置（含 skill/mcp 绑定）
├── skillconfig/     # controller / service / mapper / entity   —— Skill 配置
├── mcpconfig/       # controller / service / mapper / entity   —— MCP Server 配置
├── chat/            # ChatSessionController, ChatMessageService          —— 会话
├── agui/            # AguiRunController(/agui/run), AgentFactory, AguiEventRecorder —— AG-UI 接入
├── hitl/            # ApprovalController, ApprovalService                —— 审批/确认持久化
└── audit/           # TokenUsageListener, AuditQueryController, TokenStatsService —— 审计
```

**关键类职责：**

- `AgentFactory`：核心翻译器。输入 `agent` 配置行（含 skill/mcp 绑定），输出 `HarnessAgent`（`HarnessAgent.builder().name(...).sysPrompt(...).model(...).workspace(...)` + 注册 MCP 工具 + Skill + 中间件）。**所有 AgentScope API 调用只允许出现在 `agui/` 和 `audit/` 包**，配置包不得 import `io.agentscope`。
- `AguiRunController`：`POST /agui/run`（SSE，`text/event-stream`），接收 AG-UI `RunAgentInput`，经 `AgentFactory` 构建 agent，把 AgentScope 事件流透传为 AG-UI 事件，同时：
  1. 落库 `chat_message`；
  2. 事件里带 usage 的，写入 `token_usage`（`TokenUsageListener`）；
  3. 权限系统发出"需审批"事件时，写 `approval_record(PENDING)` 并推送审批卡事件。
- `ApprovalService`：`POST /api/approvals/{id}/decide`（approve/deny）→ 唤醒/恢复该 session 的 agent 执行（复用 AgentScope 的 HITL resume 能力）。

## 5. API 契约（冻结，前端按此开发，改动需走任务门禁）

统一响应：`{ "code": 0, "msg": "ok", "data": ... }`；非 0 为业务错误。分页：`{records, total, current, size}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | `{username,password}` → `{token, user}` |
| GET | `/api/auth/me` | 当前用户 |
| GET/POST | `/api/model-providers` | 供应商列表/新建（`api_key_cipher` 只写不回读，返回 `****`） |
| PUT/DELETE | `/api/model-providers/{id}` | 修改/删除 |
| POST | `/api/model-providers/{id}/test` | 连通性测试（发起一次最小补全），返回 `{ok, latencyMs, error}` |
| GET/POST | `/api/models`、PUT/DELETE `/api/models/{id}` | 模型 CRUD |
| GET/POST | `/api/agents`、GET/PUT/DELETE `/api/agents/{id}` | Agent CRUD（含 skillIds/mcpServerIds 绑定） |
| GET/POST | `/api/skills`、PUT/DELETE `/api/skills/{id}` | Skill CRUD |
| GET/POST | `/api/mcp-servers`、PUT/DELETE `/api/mcp-servers/{id}` | MCP CRUD |
| POST | `/api/mcp-servers/{id}/sync-tools` | 拉取工具列表，写 `tool_cache`，返回工具清单 |
| GET/POST | `/api/sessions`、DELETE `/api/sessions/{id}` | 会话列表/创建/删除 |
| GET | `/api/sessions/{id}/messages` | 历史消息 |
| POST | `/agui/run` | **SSE**，AG-UI 协议入口 |
| POST | `/api/approvals/{id}/decide` | `{decision: APPROVED\|DENIED, reason?}` |
| GET | `/api/audit/token/summary?userId&from&to` | 按用户聚合：`{userId, promptTokens, completionTokens, totalTokens, byModel[], byDay[]}` |
| GET | `/api/audit/token/records?...` | 明细分页 |
| GET | `/api/audit/token/users` | 有消耗的用户列表（管理员看全部，普通用户仅自己） |

鉴权规则：`/api/auth/login` 与 `/agui/run`（凭 `Authorization: Bearer`）外，其余全部需 JWT；`/api/audit/**` 管理员可查全员，普通用户仅本人；配置类接口仅 ADMIN。

## 6. AG-UI 事件 → 前端卡片映射（核心需求 5）

前端订阅 `/agui/run` 的 SSE 事件流，按事件类型渲染：

| AG-UI 事件（来自 agentscope-extensions-agui） | 前端组件 | 说明 |
|---|---|---|
| `TEXT_MESSAGE_CONTENT` / `TEXT_MESSAGE_START/END` | 气泡（Markdown 渲染） | 普通 assistant 气泡 |
| `TOOL_CALL_START/ARGS/END` | **工具调用卡**（折叠：工具名+参数+结果） | 通用 |
| `STATE_SNAPSHOT` / `STATE_DELTA` | （预留）状态同步，暂只打日志 | |
| 权限系统 `require_approval` 类事件（approval 请求） | **审批卡**：工具名、参数、[批准] [拒绝] 按钮 → 调 `/api/approvals/{id}/decide` | HITL 主链路 |
| `CUSTOM` event `name=confirm_card` | **确认卡**：`{title, message, options[]}` 渲染按钮，回传 option | Agent 通过 CustomEvent 主动要求确认 |
| `CUSTOM` event `name=mapping_card` | **映射卡**：`{title, columns[], rows[][]}` 渲染键值/表格 | 结构化数据展示 |
| `RUN_STARTED/RUN_FINISHED/RUN_ERROR` | 运行状态条 / 错误气泡 | |

约定（写死在两端，属接口契约）：

```ts
// CUSTOM 事件 data 结构
interface ConfirmCardData { title: string; message: string; options: {label: string; value: string}[]; requestId: string }
interface MappingCardData { title: string; columns: {key: string; label: string}[]; rows: Record<string,unknown>[] }
```

卡片组件统一放 `frontend/src/components/cards/`，均为 shadcn/ui 组合（Card + Button + Dialog 等）。

## 8. 安全与鉴权

- Spring Security 过滤器链：`/api/auth/login` 放行；其余 JWT；`/agui/run` 也走 JWT（前端用 `fetch(EventSource 不支持 header)` → 用 `@ag-ui/client` 的 fetch 注入 header）。
- 密码 BCrypt；JwtService 用 HS256，密钥来自 `JWT_SECRET` 环境变量。
- 角色：ADMIN / USER。初始化数据 `V2__seed.sql`：`admin / Admin@123`（首次登录后改）。
- 审批接口校验：只有该 session 归属用户可 decide。

## 9. Token 审计（核心需求 6）

1. `TokenUsageListener`（AgentScope 中间件/事件监听）在每次模型响应事件中提取 usage（prompt/completion tokens）。
2. 以 `requestId`（一次 `/agui/run`）为单位聚合，run 结束时写一行 `token_usage`；同 run 多轮工具循环可写多行，`request_id` 相同。
3. 汇总查询走 SQL 聚合（`GROUP BY user_id, model_id, date(created_at)`），不做实时计算。
4. 前端审计页：按用户汇总表（总 tokens、按模型分布、按日趋势折线）。

## 11. 全局防跑偏门禁（每个任务验收时逐条检查）

**G1 依赖门禁**：`pom.xml` 中 AgentScope 相关依赖坐标/版本必须与第 2.1 节一致；出现本文档未列出的新依赖（尤其自研 MCP 实现、自研事件协议、其他 agent 框架）= 不通过。

**G2 分层门禁**：`com.myagent.modelconfig/agentconfig/skillconfig/mcpconfig` 包不得出现 `import io.agentscope`；AgentScope API 只允许在 `agui/`、`audit/`、`hitl/` 包使用。

**G3 契约门禁**：后端不得修改第 5 节 API 路径/字段名；前端不得自造接口。需要变更时先改本文档并在任务记录注明。

**G4 数据门禁**：DDL 只能出现在 `src/main/resources/db/migration/`；业务代码出现 `CREATE TABLE`/`ALTER TABLE` = 不通过。

**G5 质量门禁（每任务必跑且全绿）**：

```bash
# 后端
cd backend && mvn verify          # 编译 + 单测 + Checkstyle(若配)
# 前端
cd frontend && npm run lint && npm run build && npx vitest run
```

**G6 功能门禁**：每个任务有对应的"人工验收步骤"，必须附 curl 截图/输出或页面操作路径，不允许"应该可以了"式声明。

**G7 范围门禁**：任务列表未列出的功能（RAG、语音、A2A、多租户、国际化等）一律不做；发现有价值的新需求记录到 `docs/backlog.md`，不进当前迭代。

**G8 AgentScope 用法门禁**：MCP/Skill/AG-UI/HITL 必须使用 AgentScope 官方扩展（`McpClientManager`、skill repository、`extensions-agui`、权限系统）；禁止绕过框架自己解析 MCP JSON-RPC 或自己实现审批等待逻辑。

### 12.3 统一产物表 `artifact`（`V5__artifact.sql`）

`(id, session_id FK, user_id, role[SOURCE|ARTIFACT], storage[MINIO|DB], file_name, mime,
size_bytes, sha256, minio_bucket, minio_object_key, content TEXT, status[PENDING|READY|FAILED],
source_message_id, created_at, updated_at)`
索引：`(session_id, role, id)`、`(sha256)`。

存储路由：文本类（`text/*`、json/xml/yaml/csv、md/txt/log…）→ `DB`（正文入 `content`）；其余 → `MINIO`。
同一会话内 `sha256` 相同视为重复，不重复登记。

### 12.4 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/artifacts?sessionId=` | 会话的来源文件与产物（仅属主） |
| POST | `/api/artifacts/upload` | `multipart/form-data`（`sessionId` + `file`），落库/落 MinIO 并物化到会话工作区 |
| GET | `/api/artifacts/{id}/download` | `MINIO` 返回签名直链；`DB` 直接返回文本内容 |
| DELETE | `/api/artifacts/{id}` | 删除记录与对象 |

`/agui/run` 额外接受：`forwardedProps.skillIds`（会话级技能集合）。

### 12.5 行为约定

- **MCP 工具命名**：MCP 工具在 Agent 侧统一暴露为 `<serverName>__<toolName>`（避免多 Server 同名冲突）；实现走官方 `McpClientBuilder` + `Toolkit.registerMcpClient`，只额外套一层只做「加/去前缀」的 `NamespacedMcpClientWrapper`，协议实现不落自研（G8）。管理台工具清单仍显示 Server 原始工具名。
- **产物登记（自动全收）**：每次 run 结束后对比 Agent 工作区 `.myagent-workspace/<userId>/`（实测按属主分目录，不是 threadId），
  新增或 mtime/size 变化的文件登记为 `ARTIFACT`；**排除** `agents/**/sessions/**`、`memory/**`、
  `.skills-cache/**`、`uploads/**`。登记失败不影响 run。
- **上传物化**：上传文件写到 `.myagent-workspace/<userId>/uploads/<安全文件名>`，供 Agent 用相对路径直接读取。
- **`/` 选 Skill**：选中技能并入该会话的技能集合，经 AgentScope 官方 `SkillFilter` 生效；
  内容按官方渐进式披露加载，不硬塞提示词。

### 12.6 前端

- 会话页右侧新增侧边栏，两个分区：**来源文件** / **产物**（可折叠；文本类可预览，均可下载）。
- 输入区：`/` 触发 Skill 选择（仅 ENABLED），选中后成为**不可编辑块**且可整体删除；支持上传附件。

## 13. Phase 11 增量：记忆与会话状态入库 + 输入框上方附件

> 用户 2026-10-11 第二轮新增需求。决定见 brief 的 D23 / D24。

### 13.1 现状与目标

对话消息已在 `chat_session` / `chat_message`；但 **Agent 的长期记忆**（工作区 `memory/*.md`）与**框架会话状态**（`agents/*/sessions/*.jsonl`）仍在磁盘。目标：两者都落 PostgreSQL，且 Agent 行为不变。

### 13.2 存储后端（D23，用户选 A）

全部走 AgentScope 官方 SPI，不自研记忆/状态逻辑（门禁 G8）：

| 内容 | 官方扩展点 | 平台实现 | 新表 |
|---|---|---|---|
| 框架会话状态 | `io.agentscope.core.state.AgentStateStore`（`HarnessAgent.Builder.stateStore(...)` 可替换） | PostgreSQL 版 `AgentStateStore` | `agent_state` |
| 长期记忆 | `RemoteFilesystem` + `BaseStore`（官方 SPI：`get/put/putIfVersion/search/delete`）+ `NamespaceFactory` | PostgreSQL 版 `BaseStore` + `NamespaceFactory` | `memory_store` |

DDL 经 Flyway `V6__memory_store.sql`；`State`/记忆内容以 `jsonb` 存；`memory_store` 用 `version` 做乐观锁（对应官方 `putIfVersion`）。

**实现期必须先验证**：实测 `WorkspaceManager.appendUtf8WorkspaceRelative` 经 `filesystem` 抽象，而 `readManagedWorkspaceFileUtf8` / `readMemoryMd` 部分路径直接解析本地 `Path`。因此先验证「记忆读写是否都经过可替换的 filesystem 抽象」：
- 能覆盖 → 用 `RemoteFilesystem` + PG `BaseStore`；
- 不能覆盖 → 记忆改为「写穿到库 + 读优先取库」（仍不改框架记忆逻辑）。
两条路线都必须满足验收：**记忆在库里可用 SQL 查到、Agent 仍能读到**；任务记录里写明最终采用哪条及原因。

### 13.3 附件交互（D24，用户确认）

- 附件在**浏览器端暂存**，以可移除条目显示在**输入框上方**；支持多选与追加，按「文件名+大小」去重。
- **点发送时才上传**（沿用第 12 节的存储路由与物化）；暂存期间不写库、不产生 `artifact` 行。
- 上传失败：给出明确原因，不清空输入文本、不丢其余附件；右侧栏「来源文件」行为不变。

### 13.4 前端

- `Composer` 区新增附件暂存列表（`×` 移除）；发送时先上传全部附件、再发消息。
- 与既有布局约束保持一致（消息区/输入框仍 `max-w-3xl` 居中同宽）。

### 13.5 实测结论（2026-10-11）

- **路由前缀生效**：`filesystemRoute("memory", RemoteFilesystem{PG BaseStore})` 实测可用——工作区 `memory/**` 的读写走库，
  磁盘 `memory/*.md` 不再产生（实测为 0 个文件）。官方 Builder 会把 base filesystem 与 routes 组装成 `CompositeFilesystem`（按前缀 `startsWith` 匹配）。
- **会话状态落库**：`HarnessAgent` 每轮会调用 `saveAgentState`，落库键为 `(agent_id, session_id)`；其中 `agent_id` 取
  `RuntimeContext.getUserId()`（框架语义），`session_id` 为 AG-UI 的 threadId。因此查询时要按「用户 + 会话」而不是平台 agent 主键。
- **读取确实来自库**（判决性实验 `scripts/verify-p11-memory-read.sh`）：先往 `memory_store` 种一段带随机标记的记忆 →
  删掉工作区 `memory/*.md` → 再跑一轮触发 flush → 库里那条记忆**仍含原标记且 payload 变大**。说明 flush 是先经官方文件系统
  从库读到旧内容、再追加写回，而不是从磁盘重建；因此不需要启用「写穿 + 读优先取库」的备选方案。
- **前端 FileList 的坑**：`input.files` 是「活」的 FileList，清空 `input.value` 后会变空；而 React 的状态更新函数在事件处理之后才执行，
  所以必须**先把 `Array.from(files)` 固化**再 `setState`，否则暂存区拿到空列表（实测踩过并已修）。

### 13.6 门禁

G1 依赖（新增仅官方坐标 + 现有 pg 驱动）；G2 配置类包不引 `io.agentscope`；G5 DDL 只走 Flyway；G8 只实现官方 SPI，不重写框架记忆/状态逻辑；不引入向量检索（非目标）。

## 14. Phase 12 增量：停止执行 + 子 Agent 事件卡

> 用户 2026-10-11 第三轮新增需求。决定见 brief 的 D25 / D26 / D27。

### 14.1 停止执行（D25）

- **前端**：`status=running` 时把「发送」替换为「停止」（同尺寸同位置，避免布局跳动）。点击：abort 在途 SSE → 调
  `POST /api/sessions/{id}/interrupt` → 状态回可输入 → 该条助手气泡标注「已停止」（已生成内容保留）。
- **后端**：新接口按会话 `threadId` + 当前用户定位运行中的 Agent 实例，调用**官方** `HarnessAgent.interrupt(...)`；
  没有运行中的 run 时返回 `{interrupted:false}`（不报错）。SSE 的 `onCompletion/onError/onTimeout` 里兜底触发中断，
  解决"关掉页面后端还在跑"的真实浪费。
- 落库：被停止轮次的已生成文本 + 停止标记写入 `chat_message`，刷新可回放。
- 门禁 G8：不实现自研中断/取消机制，只用官方 interrupt。

### 14.2 子 Agent 事件卡（D26）

官方 AG-UI 扩展的 `SubagentEventConverter` 会发出这族 CUSTOM 事件（`value.source` 标识子 Agent）：

| CUSTOM name | value 关键字段 |
|---|---|
| `subagent.lifecycle` | `type`(AGENT_START/AGENT_END), `name`, `replyId`, `state` |
| `subagent.text` | `type`(TEXT_BLOCK_DELTA), `delta` |
| `subagent.thinking` | `type`(THINKING_BLOCK_DELTA), `delta` |
| `subagent.tool_call` | `type`(TOOL_CALL_START/TOOL_CALL_END), `toolName`, `toolCallId`, `toolCallCount` |
| `subagent.tool_result` | `type`(TOOL_RESULT_END), `toolCallId` |
| `subagent.require_confirm` | `type`(REQUIRE_USER_CONFIRM) |

前端 reducer 增加 `subagent` 条目类型：按 `source` 分组，`text`/`thinking` 增量**追加**到同一条目（不逐 delta 建卡），
`tool_call`/`tool_result` 记录紧凑工具行，`lifecycle` 维护"生成中/已结束"。渲染与既有「工具调用组」一致：
收起一行（子 Agent 名 + 状态 + 工具次数）、展开看正文与工具行。该族事件不落库。

### 14.3 审计时间参数容错（D27）

`/api/audit/token/summary` 的 `from`/`to` 同时接受日期与完整 ISO-8601 日期时间；日期按服务端时区补齐当天起止；
非法输入返回业务错误（400），不再 500。

### 14.4 门禁

G1 依赖不变；G3 契约：本增量**新增** `POST /api/sessions/{id}/interrupt`、前端新增 `subagent` 卡片类型（需回写本节与 spec）；

## 15. Phase 13 增量：会话列表时间分组 + 输入框拖拽/粘贴
