# 登录滑动验证（拼图滑块）

## 为什么自己做，不引 npm 组件

| 备选 | 问题 |
|---|---|
| `react-slider-captcha` / `vue-drag-verify` 之类 | 答案算在前端（JS 里能直接读出来）→ 等于没防护 |
| 极验 / 网易易盾 / 腾讯防水墙 | 要外网、要企业账号、要域名白名单；内网离线不可用 |
| canvas 指纹类（fingerprintjs） | 依赖 `crypto.subtle`，**内网 http 非安全上下文里根本不存在** |

结论：自己实现「后端出图 + 后端判定」，前端只负责把拖动到的 x 发过去。

## 接口

```
GET  /api/auth/captcha                 → { required, id, background, piece, pieceY, pieceSize, width, height, ttlSeconds }
POST /api/auth/captcha/verify {id, x}   → { ticket }        // 位置对才给；错了 400 并消耗一次机会
POST /api/auth/login {username, password, captchaTicket}    // ticket 一次一用
```

- 图片是 `data:image/png;base64,...`，不依赖外网，内网也不会"验证图加载不出来"。
- `required=false` 表示服务端关了验证（`myagent.captcha.enabled=false`），前端整块不渲染。
- 登录顺序：**先验 ticket，再查账号**。所以"猜密码"必须先过滑块。

## 实现要点

- 图由 Java2D 程序生成（渐变 + 随机色块 + 干扰线 + 噪点）；拼图是从背景上真抠下来的一块，
  背景上再挖一个压暗的缺口 —— 没有任何网络图片依赖，也不画文字（不依赖字体，容器里更稳）。
- **答案只存库**（`captcha_challenge.answer_x`），不下发前端；前端只知道图和 `pieceY`。
- 容差 `tolerance=6px`（48px 的拼图，肉眼几乎看不出，脚本猜不中）。
- 一道题最多试 `max-attempts=5` 次，超过直接作废重新出题。
- 题目 TTL `ttl-seconds=120`，过期自动清（`@Scheduled` 一分钟一次）。
- 用库不用内存：后端重启 / 多副本都不会把正在登录的人踢掉。

## 配置（application.yml）

```yaml
myagent:
  captcha:
    enabled: true          # MYAGENT_CAPTCHA_ENABLED
    ttl-seconds: 120       # 一道题活多久
    tolerance: 6           # 位置容差（原图像素）
    max-attempts: 5        # 同一道题最多试几次
    cleanup-millis: 60000  # 过期清理间隔
```

## 前端交互（frontend/src/components/auth/SliderCaptcha.tsx）

**版面只占一条滑轨的高度**：拼图面板是 `position: absolute`（`bottom-full`），
平时 `invisible` 且不参与排版 —— 不会把密码框和登录按钮挤开、页面不会因为加载验证图而跳动。

- 平时：只有一条滑轨 + 「换一张」按钮。
- **按下滑块的那一刻**：拼图面板浮在滑轨上方出现（淡入 + 轻微上浮），拖动时拼图块跟着横移。
- 松手：立刻校验（前后端联动）→ 通过变绿/失败变红，**显示约 0.9s 后面板自动收起**。
- 失败会自动换一张题（旧题已作废）；登录失败后（含 ticket 过期）也会重新出题 —— ticket 是一次性的。
- 纯 DOM 事件 + 后端图片，**不依赖 `crypto.*` / `navigator.clipboard`**。
